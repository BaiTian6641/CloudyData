# SVG and PNG export evidence

**Date:** 2026-10-18
**Requirements:** CUST14 (partial)
**Platform:** x86_64 API **36** emulator (`emulator-5580`, AVD
`Medium_Phone_API_36.1`), display override 2880×1800 at 240 dpi. Prior rootable
API 37 evidence is historical; this run is API 36 and non-root.

## Implemented path

- Host-to-renderer `ExportSvg`/`ExportPng` requests; renderer serializes the current
  `#view svg`, adds SVG/XLink namespaces, and returns a typed `SvgExport`
  message with chart ID and revision.
- Host rejects exports whose chart ID/revision is no longer current, enforces a
  2 MiB bound, and validates the parsed XML: root `svg`; no `script`,
  `foreignObject`, `style`, image/iframe/object/embed; no inline `on*` event
  handlers; no non-fragment href/src; and no external `url(...)` in URL-bearing
  attributes/styles. Text
  content that happens to contain `href="http…"` or `url(http…)` is allowed;
  only resource-loading contexts are rejected.
- PNG export snapshots the chart ID/revision before asynchronous rasterization,
  serializes the current SVG, rasterizes it in an offscreen canvas, and returns a
  bounded base64 PNG with dimensions. The host validates signature, declared
  dimensions and the PNG IHDR dimensions before offering it to the SaveDocument
  picker.
- SVG and PNG have separate retained pending slots, so a fast pair of export
  requests cannot consume each other's payload.
- The worksheet adds **SVG** and **PNG** export actions only for a current rendered chart
  (not while a spec is unavailable or the renderer has failed). It opens the
  system CreateDocument picker (`image/svg+xml`); write I/O runs on
  `Dispatchers.IO`, pending SVG survives activity recreation in a ViewModel, and
  export failures use a non-fatal status instead of destroying the renderer.
- Renderer remains offline and has no SQL/file/network authority; the exported
  document contains no scripts or remote references.

  Vega padding); no fit/scale controls are exposed.
