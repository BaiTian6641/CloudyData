# Single-series Area chart evidence

**Date:** 2026-10-18
**Requirements:** CH03 (partial), chart-family expansion
**Platform:** x86_64 API 37 emulator (`emulator-5580`), 2880×1800 @ 240 dpi.
Physical Googlebook unavailable.

## Implemented semantics

- `MarkType.AREA` and `ChartKind.AREA` are persisted in the workbook.
- Area uses the same semantic query shape as Line: one dimension on Rows, one
  aggregated measure, ordered by the dimension. `COUNT`, `SUM`, `AVG`, `MIN`,
  `MAX`, and `COUNT DISTINCT` are supported through the existing query builder.
- Color-series and logarithmic-value-axis options are rejected for Area in this
  build. The workbook clears the Color shelf and log setting when switching to
  Area.
- The value axis always includes zero, regardless of the stored zero-baseline
  toggle. Explicit bounds are expanded at the zero end (minimum ≤ 0, maximum
  ≥ 0) so the area fill cannot baseline at a clipped nonzero edge. The Chart
  settings dialog hides the zero toggle for Area.
- Vega emits an `area` mark (zero baseline), a line outline, point symbols up to
  200 points, optional value labels and the existing `cloudyHit` selection
  target. No legend is emitted.
- The native summary and table remain the accessible exact-value surface.

## Limits

- Only **single-series** area. Stacked, 100%, multi-series overlapping, area
  color series, interpolation and null-policy controls are absent.
- The line outline/symbols and fill are rendered, but no pixel-level visual
  comparison or export exists.
- Area click selection uses the shared `cloudyHit` target; the automated click
  tests cover bar and line, while area selection was not added as a separate
  emulator interaction test.
- Tooltip, export/print, focus/TalkBack traversal, physical-device and
  WebView-provider qualification remain pending. CH03 is partial.
